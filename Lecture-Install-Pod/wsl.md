
### 현재 상태 확인

터미널(PowerShell 또는 CMD)을 **관리자 권한**으로 실행한 뒤 아래 명령어를 입력하세요.


PowerShell

```
wsl -l -v
```

- **목록이 뜨는 경우:** 이미 설치된 배포판이 있는 것입니다. `VERSION`이 **2**인지 확인하세요.
    
- **'wsl'은(는) 내부 또는 외부 명령...** 이 뜨는 경우: 아직 설치되지 않은 상태입니다.
    

---
### WSL2 설치 (미설치 시)

최신 윈도우(10 또는 11)라면 아래 한 줄로 끝납니다.

PowerShell

```
wsl --install
```

- 이 명령은 **WSL 기능 활성화, 가상 머신 플랫폼 활성화, 최신 리눅스 커널 다운로드, Ubuntu 설치**를 한 번에 처리합니다.
    
- 설치가 끝나면 반드시 **컴퓨터를 다시 시작**해야 합니다.

---
### WSL2 내부 구조 및 작동 원리

WSL2는 윈도우 커널 위에 직접 리눅스를 올리는 방식이 아니라, 아주 얇은 가상화 계층(Hyper-V) 위에서 진짜 리눅스 커널을 실행합니다. 덕분에 속도가 매우 빠르고 Docker나 Podman 호환성이 좋습니다.

---
### WSL2 주요 사용법 (명령어)

- **특정 배포판만 종료:**
```powershell
wsl -t podman-machine-default
```

- **WSL 전체 강제 종료 (가장 확실한 방법):** 가상 머신 자체가 꼬였거나 메모리 점유율을 즉시 낮춰야 할 때 사용합니다.
```powershell
wsl --shutdown
```

- 기본 배포판으로 접속: WSL 시작 (Start)

```powershell
wsl
```

- 특정 배포판(예: Ubuntu)으로 접속

```powershell
wsl -d Ubuntu
```


- **상태 확인:** `wsl --status`

- **배포판 삭제:** `wsl --unregister [배포판이름]` (해당 리눅스의 모든 파일이 삭제되니 주의)


---
### 파일 시스템 접근 (중요!)

윈도우 파일 탐색기 주소창에 `\\wsl$` 라고 입력해 보세요. 설치된 리눅스 내부 파일 시스템에 바로 접근할 수 있습니다.

- **성능 팁:** `docker-compose`나 Podman 볼륨 설정 시, `C:\Users\...` 경로보다는 WSL 내부 경로인 `/home/username/...` 경로에 파일을 두고 작업하는 것이 **최소 10배 이상 빠릅니다.**

---
### 네트워크 연결

WSL2는 호스트(윈도우)와 IP를 공유하는 구조입니다.

- WSL 안에서 띄운 `postgis`(5432 포트)는 윈도우 브라우저나 DB 툴(DBeaver 등)에서 그냥 `localhost:5432`로 접속하면 됩니다. (이게 안 된다면 `podman machine` 설정 문제일 확률이 높습니다.)
